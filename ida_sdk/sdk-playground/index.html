Look up DID by Wallet CHAIN

Reads DIDRegistry directly from the chain — no API, no gas. For a wallet-based DID, the identifier is did:adi:<address>; this tells you whether it actually exists on-chain, who owns it, and if it's active.

Agent Operations

Labels are yours to define — IDA stores the pairs verbatim and never interprets them. Provision fleet mints several agents against the same operator and sponsor; each gets its own DID, because every call generates a fresh key pair.
Every label must match, so each one narrows the result. Listings are scoped to the caller: an agent shows up when its operator is your own subject or a DID you own, so use an API key issued from Settings rather than a shared service key.

Provable Sponsorship CHAIN

Sponsorship is recorded on the agent record, keyed by agent DID, in the AgentTrustRegistry. The sponsor (a human/org, own wallet) calls confirmSponsorship(agentDid, sponsorDid) — the chain records msg.sender as the proven sponsor, so the operator can't forge it. Then anyone asks getSponsor(agentDid) and learns the sponsor, trusting only the chain. Prereq: the agent must already be registered on-chain (use registerAgent (signer) in Agent Operations). See docs/agent-sponsor-registry-change.md.
① SPONSOR — a human / org (their own wallet)
The sponsor can be a separate party (Generate sponsor) OR the same wallet as the operator if the operator vouches for its own agent (paste the operator key → the DID auto-fills). Whichever wallet signs becomes the proven sponsor.
② AGENT — the one being sponsored (by agent DID)
Verify only needs the agent DID — anyone can look up its sponsor without a key or gas.
